# T.R.K : BORDER LINE — เวอร์ชันปลอดภัย (Netlify)

## วิธีติดตั้ง
1. ติดตั้ง Node.js แล้วรัน `npm install` ในโฟลเดอร์นี้
2. อัปโหลดโฟลเดอร์ขึ้น GitHub แล้วเชื่อมกับ Netlify (หรือใช้ `npm i -g netlify-cli` แล้ว `netlify deploy --prod`)
   *การลากวางโฟลเดอร์ใน Netlify ไม่รองรับ Functions ต้องใช้ Git หรือ CLI*
3. ที่ Netlify → Site settings → Environment variables เพิ่มค่า:
   - `ADMIN_PASSWORD` : รหัสผ่านแอดมิน ยาวอย่างน้อย 12 ตัว (ใช้ตัวอักษรผสมตัวเลข/สัญลักษณ์)
   - `SESSION_SECRET` : สตริงสุ่มยาวอย่างน้อย 32 ตัว สร้างได้ด้วย
     `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`
   - `ALLOWED_DOWNLOAD_HOSTS` (ไม่บังคับ) : โดเมนที่อนุญาตให้ใช้เป็นลิงก์ดาวน์โหลด คั่นด้วย , ค่าเริ่มต้นคือ
     `drive.google.com,drive.usercontent.google.com,docs.google.com`
4. Deploy ใหม่ แล้วกดไอคอนเฟืองบนเว็บเพื่อเข้าแผง Admin ตั้งลิงก์ดาวน์โหลดจริง
5. ทดสอบในเครื่อง: สร้างไฟล์ `.env` (ห้ามอัปโหลดขึ้น Git) ใส่ค่าด้านบน แล้วรัน `netlify dev`

## ปิดช่องโหว่อะไรไปบ้าง
- รหัสผ่านไม่อยู่ในโค้ดหน้าเว็บอีกต่อไป ตรวจรหัสที่เซิร์ฟเวอร์ (เทียบแบบ timing-safe) และไม่มีปุ่มรีเซ็ตรหัสผ่านสาธารณะ
- เซสชันเป็นคุกกี้ HttpOnly + Secure + SameSite=Strict เซ็นด้วย HMAC หมดอายุใน 2 ชั่วโมง JavaScript อ่านไม่ได้
- จำกัดการล็อกอิน 8 ครั้ง / 15 นาที ต่อ IP และหน่วงเวลาเล็กน้อยกันเดารหัส
- เปลี่ยนค่าตั้งค่าได้เฉพาะแอดมินที่ล็อกอิน บันทึกที่เซิร์ฟเวอร์ (Netlify Blobs) ทุกคนเห็นตรงกัน
- ตรวจข้อมูลฝั่งเซิร์ฟเวอร์: ลิงก์ต้องเป็น https และอยู่ในโดเมนที่อนุญาต จำกัดความยาวข้อความ ตัดอักขระควบคุม
- ป้องกัน CSRF ด้วยการตรวจ Origin / Sec-Fetch-Site
- ลิงก์ดาวน์โหลดจริงไม่ถูกส่งไปกับหน้าเว็บ ได้รับหลังรอครบเวลาคูลดาวน์ที่เซิร์ฟเวอร์ตรวจเอง (ข้ามด้วย DevTools ไม่ได้) และจำกัดการขอ 20 ครั้ง / 10 นาที ต่อ IP
- ป้องกัน XSS: ใช้ textContent ทั้งหมด ไม่มี inline script/onclick และมี Content-Security-Policy เข้มงวด
- ตั้ง Header ความปลอดภัย: HSTS, X-Frame-Options (กัน clickjacking), nosniff, Referrer-Policy, Permissions-Policy
- เลิกใช้ Tailwind CDN / Font Awesome CDN / รูปจาก Unsplash (ลดความเสี่ยงจากสคริปต์ภายนอก) เหลือเพียง Google Fonts

## ข้อจำกัดที่ต้องรู้ (ไม่มีระบบไหนปลอดภัย 100%)
- ใครได้ลิงก์ดาวน์โหลดไปแล้วก็แชร์ต่อได้ และใครรอครบเวลาก็ได้ลิงก์ ระบบนี้กันการข้ามคูลดาวน์ ไม่ได้กันการแชร์ไฟล์
- การจำกัดจำนวนครั้ง (rate limit) เป็นแบบประมาณการ ไม่ช่วยรับมือการโจมตีแบบ DDoS ใช้ได้ดีกับการเดารหัสทั่วไป
- ลิงก์ Google Drive ไฟล์ใหญ่อาจขึ้นหน้าเตือนสแกนไวรัส ไม่ใช่บั๊กของระบบ
- ควรเปิด 2FA ให้บัญชี Netlify และ GitHub เพราะใครเข้าบัญชีได้ก็แก้ค่า ADMIN_PASSWORD ได้
- โค้ดชุดนี้ผมเขียนโดยยังไม่ได้ deploy ทดสอบจริงบน Netlify ควรลองทดสอบล็อกอิน บันทึก และกดดาวน์โหลดก่อนเปิดใช้งานจริง
